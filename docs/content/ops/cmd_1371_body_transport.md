## 1. 恒久の規律 (暫定規律(1) の昇格)

### 規律

**inbox / ntfy の本文を、shell を通る形で書くな。**
具体には、位置引数に二重引用符で本文を渡す形で
`` ` `` (backtick) ・ `$(…)` ・ 未定義の `$VAR` を書くな。

### ★規律だけでは足りぬゆえ、道具の側を三つ変えた★

| 何を | どう変えたか |
|------|--------------|
| 逃げ道 | `--body-stdin` / `--content-file` / `--body-file` = ★shell を一切通らぬ口★ (cmd_1363 で新設・cmd_1371 で既定へ) |
| 名乗り | 配達のたび `経路 / 関所 / 守り` を印字し、**entry にも `via` / `guard` / `safety` として焼く** |
| 強制 | `IW_REQUIRE_SAFE_BODY=1` を立てた呼び手には、位置引数の本文そのものを拒む |

### 書き方 (これが既定)

```bash
bash scripts/inbox_write.sh <target> --body-stdin <type> <from> <<'EOF'
本文をここへ。★記号を避ける必要は無い★ — ` も $(…) も $VAR も原文どおり届く
EOF
```

★`<<'EOF'` と単引用符で囲め★ — 裸の `<<EOF` は本文全体が展開に晒される (関所が止める)。

長文・引用符が入り組む本文は file 渡し:

```bash
# Write tool で本文を file へ書いてから
bash scripts/inbox_write.sh <target> --content-file /path/to/body.txt <type> <from>
```

## 3. 心拍 — 関所の生死を、道具の側から測る

- 関所は hook として呼ばれるたび `queue/.shell_guard_heartbeat/<鍵>` を書く。
- `inbox_write.sh` は本文を位置引数で受けた時、その心拍の**新しさ**を見る (90 秒)。
- 鍵は **`TMUX_PANE` → `CLAUDE_CODE_SESSION_ID`** の順。★関所側と道具側で必ず揃えよ★。

### ★この心拍が答える問い / 答えぬ問い★

| | |
|---|---|
| 答える | 「関所は**此の経路で**走っておるか」 |
| ★答えぬ★ | 「**此の本文が実際に検められたか**」 |

関所が見るのは *agent が書いた command 文字列 1 本* だけである。
**script の内側から `inbox_write.sh` を呼ぶ経路を、関所は元より見ておらぬ。**
`gate_nightly.sh` などの自動経路がこれに当たり、そこは `outside-pane` として正直に赤へ倒れる。

### ★言葉の線を跨がぬ★ (存在は証せるが不在は証せぬ)

- 心拍が**在る** = 関所が走ったことの**証明** (存在の証明ゆえ堅い)。
- 心拍が**無い** = ★「関所が死んでおる」の証明ではない★ = 走った証を我らが持たぬ、だけである。
- ⇒ `UNPROTECTED` は関所の生死についての断定ではなく
  **「守られておると我らは言えぬ」という、我らの側の申告**である。
  未検証を緑へ混ぜぬため、言えぬ側を赤へ倒しておる。

## 4. 本 cmd の途中で掘り当てた、★cmd_1363 の版から在った欠陥★

### (a) 長文で配達が丸ごと落ちる (規模の層)

本文を環境変数へ載せると、以後この shell が呼ぶ**全ての外部 command** の environ に本文が積まれる。
10 万字級で `ARG_MAX` を越え、**`sleep` すら exec できず lock が取れず配達が落ちる**。

- ★我らが「長文の本命」と勧めておった `--content-file` / `--body-stdin` が、まさに長文で壊れておった★
- HEAD の script で再現し **entry 0 件**を実測 (拙者が作った穴ではない)
- 手当 = 本文は **file で渡す** (path だけを環境変数へ)。
  ★python source へ補間はせぬ★ = cmd_1345 の教訓 (backslash / quote 事故) は不変。

> 家老が採った規律 **「そのgateが黙る規模の軸を選べ」** の実例。
> 本 gate が黙る軸は **本文の大きさ**であり、短い標本だけでは永久に出ぬ。

### (b) 安全な口が末尾改行を黙って落としておった

command substitution `$(…)` は末尾改行を剥がす。引用符つき heredoc の本文は必ず改行で終わるゆえ、
★「shell を通らぬ安全な口」を名乗りながら末尾の1文字を黙って落としておった★ =
本 cmd が退けておる「黙って欠ける」の小型再現。sentinel を継いでから剥がす形で是正。

### (c) ★常に赤い門を新しく作りかけた★

道具の側が `TMUX_PANE` しか鍵に見ておらなんだゆえ、pane を持たぬ経路 (将軍がそれ) は
**関所が現に生きておるのに永久に `UNPROTECTED`** を名乗る形になっておった。

- 心拍 dir に将軍の session 鍵が 329 秒前の心拍を持っておるのに、
  将軍の entry は `guard=outside-pane` であった = **二つの観測が食い違うたゆえ見つかった**。
- ★常に赤い門は信用されず、必ず外される★ — 鍵の順を関所側と揃えて是正。

## 6. ★塞げておらぬ範囲 (名乗り)★

網が狭いことが誤りなのではない。**狭いと名乗らぬことが誤りである。**

1. **script の内側からの呼出**を関所は見ておらぬ。
   関所が見るのは agent が書いた command 文字列 1 本だけ。
   → その経路は `outside-pane` / `UNPROTECTED` として**赤へ倒れる**が、止まりはせぬ。
2. **位置引数で既に食われた本文は、道具側では永久に検知できぬ。**
   証拠が道具へ届く前に消えるゆえ。★事後に session 記録から採ることはできる★ (本 cmd がそうした)。
3. **心拍は「関所が走った」ことしか言わぬ** — 「此の本文が検められた」とは言うておらぬ (§3)。
4. **雛形が散っておる — 直した範囲と、残った範囲を数で名乗る。**
   - 直した = `CLAUDE.md` / `instructions/common/protocol.md`。
     後者から `scripts/build_instructions.sh` で再生成し、
     ★`instructions/generated/*` と `.opencode/agents/*` と `AGENTS.md` = 計 38 file すべてに
     新しい既定が入ったことを実測した★ (`body-stdin` / `by-construction` / `UNPROTECTED` の
     3語すべてで 38/38)。
   - ★残った = 5 file★ (いずれも位置引数の例のみを持ち、新しい既定を持たぬ):
     `instructions/karo.md` / `instructions/ashigaru.md` / `instructions/gunshi.md` /
     `.cursor/skills/inbox-write/SKILL.md` / `CONTRIBUTING.md`。
   - ★これらは役職別の source であり、生成物には protocol.md 由来の新しい節も併せて入る★ =
     agent は両方を目にする。ゆえに **実害は「古い形も見える」までであって、
     新しい既定が届いておらぬのではない**。
   - ★但し併存は誤読を生みうる★ ゆえ、書換の要否は家老の裁定を仰ぐ (本 cmd の scope は
     暫定規律の恒久化であり、全雛形の書換ではない)。
