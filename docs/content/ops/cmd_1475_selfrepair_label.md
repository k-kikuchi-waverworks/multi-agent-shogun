# 自己修正の cmd を殿が承認できる形にする (cmd_1475)

作成: 足軽一号 / 2026-07-28 20:10〜20:40 JST

殿のご下命 (20:0x):

> 自己修正タスクも automate-engine に掲載されてるようにしておいて
> (自己修正というラベルを付与するなどして分かりやすくして)

---

## 1. 何ゆえ要るか

19:21 に「自己修正は禁止。cmd を起票し、殿の承認を得てから着手する」と決まった。
**殿が承認なさる場所が要る。それが engine の backlog 画面である。**

ところが台帳 (`queue/shogun_to_karo.yaml`) には「その cmd が自己修正か」を判じられる欄が
無かった。**惜しい代わりの目印はあるが、どれも一致しない**:

| 代わりの目印 | 何ゆえ使えぬか |
|---|---|
| `project: multi-agent-shogun` | 殿がご下命になった分も混ざる |
| `origin: karo` | 家老が殿由来の cmd を起票することも在る |

代わりの目印で当てると、**殿が誤った物を承認なさる**。ゆえに起票時に明示する欄を持たせた。

---

## 2. 台帳に足した 2 欄

```yaml
- id: cmd_1462
  self_repair: true       # true = この仕組み自身の改修 (殿の承認が要る)
  approval: awaiting      # awaiting | approved | rejected
```

| 欄 | 値 | 意味 |
|---|---|---|
| `self_repair` | `true` | multi-agent-shogun 自身の改修。殿の承認を待つ |
| | `false` | 殿の指令そのもの。承認は要らぬ |
| | **欄が無い** | **未記入 = まだ誰も判じていない** |
| `approval` | `awaiting` / `approved` / `rejected` | 承認の状態。`self_repair: true` の時だけ意味を持つ |

**★未記入を `false` と読まない★** — これがこの仕掛けの芯である。
未記入を「殿のご下命」と読むと、承認の要る cmd が画面から消え、
殿が「承認すべき物は無い」と誤って読まれる。
読めない値が入っていた時も、黙って未記入へ寄せず「値が不正」と名乗る。

---

## 3. 書き方

### 起票と同時に書く (これが本筋)

```bash
bash scripts/cmd_id_alloc.sh --title "短名" --origin karo \
    --project multi-agent-shogun --priority medium \
    --self-repair true --evidence "1行根拠"
```

`--self-repair true` を付けると `approval: awaiting` も一緒に書かれる (承認待ちとして起きる)。
**省略すれば欄を書かない (= 未記入)。既定値を勝手に入れない。**

### 後から書く / 承認の結果を入れる

```bash
python3 scripts/cmd_approval.py --cmd cmd_1462 --approval approved
python3 scripts/cmd_approval.py --cmd cmd_1480 --self-repair false
```

この script は**その行だけ差し替え、他の行には 1 バイトも触らない**。
書いた後に必ず検め (`ledger_validate.py` + 読み直して照合)、通らなければ元へ戻す。
錠は `cmd_id_alloc.sh` と同じ物を取るので、採番の追記と同時に走っても互いの分を消さない。

自己検査: `python3 scripts/cmd_approval.py --selftest` (陽性 9 本・陰性 7 本)。

## 4. 画面での見え方 (`/backlog`)

- 冒頭に **「自己修正で承認待ち: N 件」**。
  **同じ行に母数を出す** = 「母集団 M 件のうち、未記入 K 件」。
  0 件を見た者が、現に 0 件なのか誰も記入していないのかを、その行だけで読み分けられる。
- 一覧に **「承認」列**。自己修正の cmd だけ「自己修正 / 承認待ち」の二段で出る。
  自己修正でない cmd に承認の状態は出さない (要らぬ物を出すと承認待ちに見える)。
- **区分の絞り込み**: 全て / 自己修正 / 殿のご下命 / 未記入 (`?kind=self_repair`)。
  origin の絞り込みと併用できる。
- §0 集計に 2 表。自己修正の 4 区分は**足すと母集団と同じ数**になる。
  承認の状態は**自己修正の cmd だけ**を数える (殿の指令を混ぜると承認待ちが水増しされる)。

**engine から台帳へ書く口は作っていない。** 画面は読むだけである。理由は §6。

- cmd_1462 / cmd_1473 = `defer.reason` の逐語「殿のご指示(19:21)= 自己修正は着手禁止。承認待ちとして置く」

**家老の命は 1462/1470/1472/1473/1474 の 5 件を承認待ちとして並べる形だったが、
cmd_1474 だけは台帳自身が「自己修正とは別」と書いているので `false` にした。**
台帳の本文と命が食い違った所で、台帳の側を採った。

**残る 110 件は未記入のままにした。** 判定を推測で埋めると、殿が誤った物を承認なさるためである。

## 6. この仕掛けが覆っていない範囲 (先に名乗る)

1. **engine から承認を押せない。** 殿は一覧を見て、家老へ伝える形になる。
   理由は測った上での判断である: engine の backlog は「queue YAML の読取射影・書込ゼロ」を
   設計の芯にしており (`parser.ts` 冒頭)、書く口を足すと台帳の書き手が 2 つになる。
   加えて台帳の守り (`ledger_guard.sh`) が**正しい台帳を壊れたと判じて巻き戻す不具合が
   今 開いたままである** (cmd_1472)。その上に新しい書き手を足すのは順序が逆と判じた。
2. **未記入 110 件は誰も判じていない。** 画面はその数を出すが、埋めはしない。
3. **起票の時に `--self-repair` を付け忘れても止まらない。** 必須にしていない。
   必須にすると、既存の起票の呼び方が全部 落ちるためである。**未記入として残るだけで、
   画面の「未記入」の数に必ず現れる。**
4. **画面は台帳しか見ない。** task YAML や報告に書かれた「自己修正」の語は数えない。
