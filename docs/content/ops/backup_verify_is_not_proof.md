# 控えの検査は「戻せる証拠」になりません (2026-07-29)

見つけた人: 足軽五号（指摘）と軍師一号（撃ち直し）の2人 / 日付: 2026-07-29 / 対象: git bundle による控え

足軽五号が「16:12 の確認は本当に戻せることを見たのか」と指摘し、それを受けて軍師一号が自分の確認を撃ち直しました。**1人では出なかった発見です。** 指摘だけでは実測になりませんし、撃ち直す側は自分の確認を疑うきっかけを持ちませんでした。どちらが欠けても出ていません。

---

## 1. 何を撃って、何が返ったか

控え A の bundle は **44,685,740 byte** です。その **頭 1,000,000 byte だけ**を切り出しました。**97.8% を捨てた壊れたファイル**です。

これに検査を撃つと、こう返りました。

```
git bundle verify → rc=0
The bundle records a complete history.
```

本物の bundle と同じ文言です。次に、実際に取り出してみました。

```
git clone → fatal: early EOF
            index-pack died
```

**97.8% を捨てた壊れた控えが、検査では「完全な履歴です」と緑を返します。**

軍師一号の言葉: 「私の 16:12 の確認は、戻せることの証拠になっていませんでした」。自分の前の仕事を、自分で無効にした形です。

## 2. もう1つ出たこと — repo の外では中身を見ません

```
（repo の外で）git bundle verify → rc=1
need a repository to verify a bundle
```

**中身を1バイトも読まずに落ちます。** 控えの置き場は普通 repo の外です。そこで rc だけを見る仕掛けは、中身を見ないまま赤を返します。

つまり `git bundle verify` の rc は、**緑も赤も中身を表していません**。

## 3. 将軍が決めたこと (2026-07-29 18:2x)

- 控えが戻ることの証拠は、**現に戻したこと（clone / 取り出し）だけ**とします
- `verify` の rc は、戻せることの証拠として使いません

## 4. 何と比べるか — 控えを採った時の姿

足軽五号の申し送りです。

> 「控えが今の repo と一致するか」は、時が経てば必ず外れます。見るべきは「控えが、控えを採った時の姿を持っているか」です。混ぜると、正しい控えを「壊れている」と読む日が来ます。

机上の話ではなく、現に起きています。追跡下のファイル数（実測）:

```
6b64914（束0を採った 15:55） = 412 本
66d8aea = 413 本 / 8450968 = 413 本 / 3f1f8e5 = 414 本
```

束0の後に足軽三号（この文書の書き手）が commit を 3 つ積んだので、今の repo と比べれば必ず差が出ます。**控えは 15:55 の姿を正しく持っており、ずれたのは比べる相手の側です。**

§3 と対で使ってください。**§3 = 何をもって証拠とするか（検査の緑ではなく、現に戻したこと）／§4 = 何と比べるか（今の repo ではなく、控えを採った時の姿）。** 片方だけだと、次に読む人が正しい控えを「壊れている」と読みます。

## 5. 殿の言葉との関係

殿は前から、控えは **「在るか」でなく「今 現に戻せるか」で数えよ** と言われています。

今回の実測は、その言い方でなければならない理由を現物で示しました。「在るか」で数えると、97.8% 欠けたファイルが 1 本として数えられます。検査も緑を返すので、数えた側は最後まで気付けません。**「現に戻せるか」で数えて初めて、この控えは 0 本になります。**
