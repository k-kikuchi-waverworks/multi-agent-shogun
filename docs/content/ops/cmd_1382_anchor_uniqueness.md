# cmd_1382: 着弾の一意性 — 「確かめた」と「運が良かった」を分ける

> ★anchor が非一意なら、狙いは黙って別の場所へ着弾する★。
> ★これは空振りではない = 撃ってはおる。撃つ場所が違う★ — 家老 規律(8) (2026-07-26)

## なぜ在るか (これが分からねば次の者が消す)

変異試験は「わざと壊せば test が赤くなる」を確かめる。だが **その赤が、狙った場所の赤とは限らぬ**。

実害 (五号・2026-07-26): 変異の anchor (置換する綴り) が一意でなく、**旧い同名の関数と被っておった**。
`replace(old, new, 1)` は先頭を取るゆえ、**先に在る旧い方を撃っておった**。

**ここが肝である**: これは空振りではない。

| | byte は変わるか | test は赤くなるか | 既存の層で捕まるか |
|---|---|---|---|
| 空振り (anchor が当たらぬ) | 変わらぬ | — | ✅ `mutate 空振り` = UNDETERMINED |
| **非一意 (狙いが別所へ着弾)** | **変わる** | **赤くなる** | ❌ **原理的に捕えられぬ** |

四号が朝に据えた guard (変異前後で byte 一致なら UNDETERMINED) は
**【当たったか】を見ておるが【狙った場所に当たったか】は見ておらぬ**。

## 症状は二種 (六号の census で両方 実在を確認)

- **(a) 巻き込み型** — `sed` に count 指定が無い形 → **狙い + 余所も同時に撃つ**
- **(b) 移動型** — `python replace(old, new, 1)` 形 → **着弾は 1 箇所だが、それが狙いとは限らぬ**

(b) が危ういのは **着弾数を数えても 1 に見える** ゆえである。

## 測り方 — 二射法 (静的に anchor を読まぬ理由)

台帳の `mutate` は 119 通りの綴りで書かれておる (`sed` / `python` heredoc / `cat >>` /
`printf >>` / 複数 sed の束ね)。**綴りを読んで anchor を取り出す道は必ず取りこぼす**。
ゆえに **実際に撃って数える**:

1. **第1射** — pristine へ `mutate` を当て、**文字単位の編集片**を採る。
   **同一の (消えた綴り → 現れた綴り) が n 回現れたら n 箇所で発火した** = (a)。
   - ★行単位では数えられぬ★: 隣り合う行が同じ pattern で撃たれると difflib は 1 塊に畳み、
     **3 箇所を撃った sed が「1 箇所」に見えた** (本層の陽性対照が実際にそう出た)。
   - ★空白のみの組は数から外す★: 多行 block の字下げ直しが n 発火に見える偽陽性を実測で潰した。
2. **第2射** — 第1射の結果へ **同じ mutate をもう一度**当てる。
   - 第1射が**触れておらぬ行**を撃った → **別の候補が残っておった** = (b)。
   - 第2射が己の守り (`assert old in s` 等) で落ちた → **候補が尽きた証** = 一意。

### 宣言 — `anchor_sites: N`

意図的な全置換は禁じておらぬ。**黙って全置換することを禁じておる**。
N 箇所で発火するのが意図なら台帳へ `anchor_sites: N` と書け (既定 1)。
**過小申告は鳴る** (申告が飾りにならぬ形・selftest T42)。

## ★この網が答えぬ問い★ (名乗っておく)

消えたら赤くなる形で selftest が縛っておるが、**限界そのものは消せぬ**:

1. **一意であることは、其の1箇所が【狙った場所】である事を意味せぬ**。
   「一意か」と「狙った場所か」は**別の問い**である (狙いは `red_needle` が別に縛る)。
2. **第1射が自らの産物を食う形では、第2射が同じ場所へ戻るゆえ、その先に第2候補が在っても見えぬ**。
   この型は mutate 側で `assert s.count(old) == 1` を書くのが唯一の確かな道である
   (census では該当 8 件を **literal 数え上げで individually 裏取り**した)。
3. **一意でも波及が広ければ同じ穴** (規律(8) 第三の型・軍師二号)。
   共有 helper を撃てば anchor は一意でも赤の出所が絞れぬ。**本層は波及の広さを測っておらぬ**。

## 軍師一号の追補は門になるか — ★ならぬ★

追補: **【緑を根拠に穴を申し立てる時は、着弾の証明を先に出せ】**

**これは門にならぬ。人の作法として docs へ据える。** 理由を機械の言葉で述べる:

- 門が判ずるには「**この申し立ては緑を根拠にしておるか**」を機械が読めねばならぬ。
  だが申し立ては report / inbox / commit message の**自然文**であり、
  「緑ゆえ穴が在る」という**論証の形**は綴りに現れぬ (「PASS」の語が在るかでは測れぬ)。
- 仮に測れたとしても、**門が止められるのは綴りであって論証ではない**。
  「着弾の証明を添えた」と**書くこと**は容易く、**書いた事と証した事の食い違い**は
  まさに本日ずっと潰してきた型 (札が嘘をつける形) を**新設する**ことになる。
- ★ゆえに、これを門にすれば【作法を守った振り】を機械が承認する道を作る★。
  機構を増やして守りが減る、最も悪い形である。

**代わりに何が効くか**: 追補が防ごうとした失敗 (当たっておらぬ変異の緑を「門の穴」の根拠に使う)
は、**本層 (着弾の一意性) が機械の側から塞ぐ**。着弾しておらぬ / 別所へ着弾しておれば、
その entry は UNDETERMINED として名指されるゆえ、**そもそも緑を根拠にできぬ**。
人の作法として残すのは、**台帳の外で行う申し立て** (report での所見) の分だけである。

## 第二の数え方 — 波及の広さ (規律(8) 第三の型・軍師二号)

**anchor の一意性とは別の数え方である**:

- (a) anchor が何箇所で発火したか … 上の二射法 (**着弾の数**)
- (b) **撃った当の物が、何本の試験から使われておるか** … こちら (**波及の広さ**)

(b) が大きければ、**一意でも赤の出所が絞れぬ**。

| 撃っておる当の物 | 件数 |
|---|---|
| production code | 82 |
| **試験の足場 (tests/ harness/ conftest 等)** | **37** |
| 計 | 119 |

**★型(c) の疑い = 37 件★** (全体の 31%)。最も重いのは 3 件が
`tests/harness/live_form.py` を撃っておる形 (同 file を参照する試験 26 本)、
次いで `tests/conftest.py` 4 件 (同 15 本)、`tests/harness/arm_compare.py` 17 件 (同 8 本)。
**いずれも backend 台帳**である (shogun / engine / web / app には 0 件)。

### ★この数の限界を先に名乗る★

参照数は **撃った file の basename の literal 一致**で数えておる。ゆえに:

- **過大に出る**: `module.py` / `main.py` の様な**ありふれた綴り**は無関係な行を拾う。
  実測で `modules/game_context/module.py` が「158 本」と出たが、これは
  **`module` という語が至る所に在るゆえ**であり、**信ずるに足らぬ**。
- **過小に出る**: 動的 import や re-export は追えぬ。

⇒ **数は目安に過ぎぬ。信ずるに足るのは「試験の足場を撃っておるか」の path による分類の側**である
(こちらは綴りでなく置き場で判ずるゆえ)。**本任は 37 件を名指すまでとし、
個々が本当に「狙い1点でない」かの判定は所有者の手番とする** (他人の牙は書き換えておらぬ)。

**本層 (門) はこの (b) を測っておらぬ** — 測れば全 entry の 31% が鳴り、
**常に鳴る門になって外される**。まず所有者へ回すのが順である。

## 配線

`gate_mutation_replay.py` の `evaluate_entry` へ **③b** として挿した =
**既存の gate に相乗りしておる (機構を増やしておらぬ)**。replay は元より mutate を当てておるゆえ、
費用は **1 entry あたり mutate 1 回分**である。5 台帳すべてが同じ runner を通るゆえ、
**1 箇所の是正で全台帳に効く**。

判定は **UNDETERMINED** = ★未検分は緑ではない。だが牙が折れた FAIL とも違う★。

**配線前に鳴る数 = 4 件** (上表)。**鳴る物の扱い**: 所有者が `anchor_sites` を申告するか
anchor を絞るまで鳴り続ける。**これは正しい振舞いである** (借金の取り立てと同じ形)。
